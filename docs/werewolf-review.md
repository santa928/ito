# 人狼モードの仕様と検証

対象: [Issue #4](https://github.com/santa928/ito/issues/4)。通常モードの配札と100→1の判定を維持し、独立した人狼の進行を追加する。

## 採用仕様

| 項目 | 仕様と理由 |
|---|---|
| 人数・配札 | 4〜8人、1人1枚、人狼1人。通常モードは2〜3人で2枚、4〜8人で1枚を維持 |
| 並び・公開 | 人狼は1→100。確認ダイアログで取消可能。数字公開後は並び・お題を変更不可 |
| 正解 | 投票を経ず市民勝利。結果で役職を公開 |
| 議論 | 手動で60秒開始。中断中も時間が進み、期限後に手動で投票へ進む。受け渡し準備のため自動遷移しない |
| 投票 | 順番に端末を渡して本人だけが選択。自己投票・棄権なし。全員の確定後に集計。未確定選択は中断・隠す操作・終了確認で消去 |
| 同票 | 最多票候補に1回再投票。再同票は人狼勝利。指名を1人に絞るルールを保ち、再投票を無期限に繰り返さない |
| 無投票 | 結果へ進まず本人の操作を待つ |
| 勝敗・再戦 | 最多票の1人が人狼なら市民勝利、ほかなら人狼勝利。再戦は数字・役職・議論・投票・勝敗を初期化 |

数字と役職は押下中だけDOMへ置く。受け渡し・blur・pagehide・visibilitychange・pointercancelで消す。数字公開後、役職は勝敗確定まで表示せず、カード再確認の導線も出さない。

## 検証範囲

- unit 109件、lint、TypeScript/build成功。
- ChromiumモバイルE2E 30件成功。通常2/3/8人と人狼4/8人の完走・再戦、正解直行、捕捉、逃亡、再同票、投票の中断と秘密解除を確認。
- Chromium CDPのタッチ入力で、長押しの微小移動時の位置・表示維持、領域外・解放・キャンセル時の数字と役職の解除を確認。
- 8人・24文字の同名で議論、投票の受け渡し、候補選択、結果の320/390/430pxを検査。横overflowなし、操作領域44px以上。代表スクリーンショットを目視し、文字や数字の欠け・重なりがないことを確認。
- 独立コードレビューと追加テスト後の再レビューで、未解決の指摘なし。

WebKitはLinux arm64のPlaywright 1.59.1コンテナ内で、Xvfb上のGTK版（`--headed`）を使用した。通常・人狼の全分岐22件と、幅検証の修正後6件、計28件が成功。2件のCDP専用タッチ検証はWebKitでは対象外で、Chromiumで実行した。

headless WPE版は既存ホーム操作でもプロセス終了が発生し、描画ドライバのエラーを伴う。変更前mainでも再現した引継ぎ記録があり、今回の追加コードだけの回帰とは確認されていない。WPE版の根本原因は未特定で、合格扱いにはしていない。

GTK版の実行中のviewport変更では、`innerWidth`と実際のレイアウト・画像の幅が一致せず、前のサイズが残ることを実測した。各幅を起動時に指定した新しいcontextでは一致するため、ホーム・人狼の幅検証を独立したケースにし、`clientWidth`が指定幅と同じことも検査した。実行中のresizeへの追従は、この環境での検証対象外。

## PWA更新と配信量

lock準拠の`npm ci`後に最終`test:pwa`が成功。旧autoUpdate版から現行prompt版への移行、次のprompt版への更新中のラウンド・結果保持、ホームへ戻るだけでは再読込しないこと、明示更新だけで再読込することを確認した。並べ替え操作のp95は約13.8msで、100msの基準内。

配信量ゲートは、承認を受けてSW移行用の旧版と比較基準を分離した。Issue #4着手前mainの固定SHA `b72d94f9160b0250888fe3ca26186dfe8dea253a`からの増分に、従来と同じ10KiB上限を適用する。SW世代間検証は旧版 `e0b8e3cc5620a12bbda8d88af1d34c1aaeea4b72`を維持する。動くmain参照へ置き換えず、両SHAと両基準量をreportへ保存する。

| build | JS+CSS gzip bytes |
|---|---:|
| 旧autoUpdate版 `e0b8e3c` | 80,885 |
| 変更前main `b72d94f` | 89,841 |
| 人狼追加版 | 93,252 |

今回の増分は変更前mainから3,411 bytesで、10KiB以内。旧版からの累積12,367 bytesは別項目として残す（旧累積ゲートでは2,127 bytes超過）。更新機能・操作時間・今回の増分ゲートをすべて通過し、比較基準分離後の独立再レビューにも未解決指摘はない。

依存は変更していない。既存lockのauditはhigh 1件・moderate 1件で、ESLintとPWAビルドからの推移依存`brace-expansion`・`fast-uri`が対象。今回の差分で追加された指摘ではなく、依存更新は未実施。

## 検証の限界

実機iPhoneのSafari、ホーム画面からの起動、VoiceOver、対面プレイは未実施。ブラウザの端末エミュレーションは実機確認の代わりにはならない。

ゲームバランスは未検証。市民の自然な並べ間違いに人狼が便乗する回、数字公開後に人狼が明白な回、近い数字と大きく偽る数字の違い、特に4人・7〜8人の面白さは対面プレイで評価する。
